# ② 단계 테스트: 텍스트 → 의도 분류 (소형 LLM)

목표: STT 결과 텍스트를 `safeaid_core.py`의 고정 `scenario_id` 중 하나로 분류하는 JSON을 만든다. LLM은 응급처치 내용을 생성하지 않고 **라우팅용 분류 결과만 반환**한다.

## 결론: Ollama 우선, GPU는 실측, 필요시 llama.cpp CUDA

Jetson Xavier NX를 쓰는 이유는 GPU 가속이다. 하지만 **Ollama가 Xavier NX에서 항상 GPU를 안정적으로 쓴다고 전제하면 안 된다.**

따라서 의도분류 단계는 이렇게 운영한다.

1. **1순위:** Ollama + `qwen2.5:1.5b`
2. `jtop`/`tegrastats`로 GPU 사용 여부와 응답시간 측정
3. Ollama가 CPU로만 돌아도 웜 응답이 목표 안이면 유지
4. Ollama가 느리거나 불안정하면 **llama.cpp CUDA 빌드 + Qwen2.5 1.5B GGUF**로 전환

즉 "Ollama GPU가 안 잡힘 = Jetson 실패"가 아니다. Jetson GPU는 여전히 STT/비전/TensorRT에서 쓰고, LLM 실행기는 실측 결과에 따라 고른다.

## 앱의 실제 계약

`smartaid-kit/app.py`의 `classify_with_optional_ollama()` 계약을 따른다.

- 엔드포인트: `http://127.0.0.1:11434/api/generate`
- 환경변수: `SAFEAID_USE_OLLAMA=1`
- 기본 모델: `SAFEAID_OLLAMA_MODEL=qwen2.5:1.5b`
- 요청: `stream: false`, `format: "json"`
- 출력:

```json
{ "scenario_id": "bleeding", "confidence": "medium", "risk_flags": [] }
```

허용 `scenario_id`:

```text
bleeding, cut, burn, foreign_object, splint, hypothermia, heat, co, bite
```

유효하지 않은 JSON이나 알 수 없는 `scenario_id`는 앱에서 키워드 분류기로 폴백한다.

## 1. Ollama 설치와 모델 준비

```bash
curl -fsSL https://ollama.com/install.sh | sh
systemctl status ollama
ollama pull qwen2.5:1.5b
ollama --version
```

서비스 재시작:

```bash
sudo systemctl restart ollama
```

## 2. Ollama 단독 성능 확인

```bash
ollama run --verbose qwen2.5:1.5b "피가 나 -> 아래 중 하나로만 JSON 분류: bleeding, cut, burn, foreign_object, splint, hypothermia, heat, co, bite"
```

기록할 값:

- 콜드 로딩 시간
- 웜 응답 시간
- token/s
- RAM/SWAP 피크
- `jtop`의 GPU 사용률
- `tegrastats`의 `GR3D_FREQ`

GPU 사용률이 안 올라가도 바로 실패 처리하지 않는다. 웜 응답이 2초 안쪽이면 데모에는 충분할 수 있다.

## 3. 작품 계약 검증 스크립트

```python
# ~/safeaid_ai/llm/classify_test.py
import json
import time
import urllib.request

MODEL = "qwen2.5:1.5b"
SCENARIO_IDS = [
    "bleeding",
    "cut",
    "burn",
    "foreign_object",
    "splint",
    "hypothermia",
    "heat",
    "co",
    "bite",
]

CASES = [
    ("피가 많이 나", "bleeding"),
    ("손을 베였어", "cut"),
    ("뜨거운 물에 데었어", "burn"),
    ("유리가 박혔어", "foreign_object"),
    ("팔이 부러진 것 같아", "splint"),
    ("몸이 너무 차가워", "hypothermia"),
    ("너무 더워서 어지러워", "heat"),
    ("일산화탄소 경보가 울려", "co"),
    ("벌레에 물렸어", "bite"),
]

def classify(text: str) -> dict:
    prompt = {
        "instruction": "응급처치 방법을 생성하지 말고 사용자 발화를 scenario_id 중 하나로만 분류해 JSON만 반환하세요.",
        "scenario_ids": SCENARIO_IDS,
        "text": text,
        "schema": {
            "scenario_id": "string",
            "confidence": "low|medium|high",
            "risk_flags": ["string"],
        },
    }
    body = json.dumps(
        {
            "model": MODEL,
            "prompt": json.dumps(prompt, ensure_ascii=False),
            "stream": False,
            "format": "json",
        },
        ensure_ascii=False,
    ).encode("utf-8")
    req = urllib.request.Request(
        "http://127.0.0.1:11434/api/generate",
        data=body,
        headers={"Content-Type": "application/json"},
        method="POST",
    )
    t0 = time.time()
    with urllib.request.urlopen(req, timeout=12) as r:
        payload = json.loads(r.read().decode("utf-8"))
    parsed = json.loads(payload.get("response", "{}"))
    sec = round(time.time() - t0, 2)
    return {"text": text, "parsed": parsed, "sec": sec}

if __name__ == "__main__":
    ok_count = 0
    for text, expected in CASES:
        result = classify(text)
        actual = result["parsed"].get("scenario_id")
        valid = actual in SCENARIO_IDS
        ok = valid and actual == expected
        ok_count += int(ok)
        mark = "O" if ok else "X"
        print(f"[{mark}] {text} -> {actual} expected={expected} sec={result['sec']} parsed={result['parsed']}")
    print(f"accuracy={ok_count}/{len(CASES)}")
```

실행:

```bash
source ~/safeaid_ai/venv/bin/activate
python ~/safeaid_ai/llm/classify_test.py
```

## 4. 재고 질문은 별도 경로

`"후시딘 있어?"`, `"밴드 어디 있어?"` 같은 문장은 `scenario_id` 분류 문제가 아니라 **재고 검색 문제**다. 현재 앱 기준으로는 `/api/classify`가 아니라 `/api/inventory/query` 경로에서 검증해야 한다.

따라서 LLM 분류 정확도 표에는 재고 질문을 섞지 않는다. 통합 테스트 문서에서 별도로 다룬다.

## 5. llama.cpp CUDA 대체 경로

Ollama가 다음 중 하나에 해당하면 llama.cpp를 검토한다.

- 웜 응답이 2초를 계속 넘는다.
- 콜드 로딩이 너무 길어 데모 리허설이 불안정하다.
- Ollama 서비스가 Xavier NX에서 자주 죽는다.
- GPU를 전혀 쓰지 않고 CPU 부하로 다른 기능을 방해한다.

빌드:

```bash
cd ~/safeaid_ai/llm
git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp
cmake -B build -DGGML_CUDA=ON
cmake --build build -j --config Release
```

모델은 Qwen2.5 1.5B Instruct 계열의 합법적으로 배포되는 GGUF 양자화 모델을 사용한다. 예: Q4_K_M 또는 Q5_K_M. 모델 출처와 파일명을 `results/versions.md`에 기록한다.

llama.cpp로 전환하면 앱의 Ollama 호출부를 그대로 쓸 수 없으므로, 최종 연동 전에는 다음 중 하나를 선택해야 한다.

- Ollama 유지: 앱 수정 최소, 응답시간이 충분하면 이 경로가 가장 단순하다.
- llama.cpp 서버/어댑터 추가: 성능은 좋아질 수 있지만 앱 연동 코드가 늘어난다.
