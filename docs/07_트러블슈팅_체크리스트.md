# 트러블슈팅 & 최종 체크리스트

## 1. Jetson 기본 문제

### 추론이 너무 느리다

- `sudo nvpmodel -q --verbose`로 최대 성능 모드인지 확인한다.
- `sudo jetson_clocks`를 적용한다.
- `jtop`에서 온도와 쓰로틀링을 확인한다.
- SD 카드라면 모델 로딩 I/O 병목을 의심하고 NVMe SSD를 검토한다.
- 콜드 런만 느린지, 웜 런도 느린지 분리해서 기록한다.

### 부팅마다 성능 모드가 풀린다

`jetson_clocks`를 systemd 서비스로 등록한다.

```bash
sudo nano /etc/systemd/system/jetson-clocks.service
```

```ini
[Unit]
Description=Max performance clocks
After=multi-user.target

[Service]
Type=oneshot
ExecStart=/usr/bin/jetson_clocks

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable jetson-clocks.service
```

### 메모리 부족 또는 프로세스 종료

- `free -h`와 `jtop`에서 SWAP 사용량을 본다.
- 모델을 동시에 올리고 있지 않은지 확인한다.
- STT small, LLM 1.5B, 비전 경량 모델 기준으로 낮춘다.
- 스왑은 안전망일 뿐이다. 추론 중 스왑을 많이 쓰면 모델/실행 순서를 다시 줄인다.

## 2. CUDA/GPU 문제

### `nvidia-smi`가 없다

정상이다. Jetson은 일반 PC GPU와 달리 `nvidia-smi` 대신 `jtop` 또는 `tegrastats`를 쓴다.

```bash
sudo tegrastats
```

`GR3D_FREQ`가 GPU 사용률이다.

### PyTorch CUDA가 안 잡힌다

- 일반 PyPI `torch`를 설치했을 가능성이 크다.
- JetPack 5.1.x에 맞는 NVIDIA 제공 PyTorch 휠을 설치한다.
- 가상환경을 `--system-site-packages`로 만들었는지 확인한다.
- JetPack, CUDA, PyTorch, torchvision 버전을 한 세대로 맞춘다.

### whisper.cpp CUDA 빌드가 안 된다

- `cmake -B build -DGGML_CUDA=1` 또는 현재 버전에 맞는 CUDA 옵션을 확인한다.
- CUDA Toolkit 경로가 있는지 `/usr/local/cuda/bin/nvcc --version`으로 확인한다.
- CPU 빌드로 기능 확인은 가능하지만 최종 데모 전에는 CUDA 빌드 문제를 해결한다.

## 3. LLM 문제

### Ollama가 GPU를 안 쓰는 것 같다

이 문제는 예상 가능한 리스크다. Xavier NX에서 Ollama GPU 가속은 반드시 실측해야 한다.

확인:

```bash
ollama run --verbose qwen2.5:1.5b "피가 나"
sudo tegrastats
```

판단:

- 웜 응답이 2초 이내면 Ollama를 유지해도 된다.
- GPU를 못 쓰고 웜 응답도 느리면 llama.cpp CUDA로 전환한다.
- 기능이 안정적이면 "Ollama CPU 실행"도 데모 경로로 허용할 수 있다.

### Ollama 서비스가 죽는다

```bash
sudo systemctl status ollama
sudo journalctl -u ollama --no-pager -n 80
sudo systemctl restart ollama
```

메모리 부족이면 모델을 1.5B 이하로 유지하고, 동시에 올라간 다른 모델을 내린다.

### JSON이 깨진다

- `format: "json"` 요청을 쓰는지 확인한다.
- 프롬프트에 "JSON만 반환"을 명시한다.
- 앱의 폴백이 동작하는지 확인한다.
- 잘못된 출력 예시는 `results/llm_result.md`에 저장한다.

### scenario_id가 부족하다

테스트 목록은 4개가 아니라 9개 전체여야 한다.

```text
bleeding, cut, burn, foreign_object, splint, hypothermia, heat, co, bite
```

## 4. STT 문제

### 한국어 오인식이 많다

- `-l ko`를 강제했는지 확인한다.
- 마이크 거리와 주변 소음을 줄인다.
- 16kHz mono wav 변환을 확인한다.
- small이 부족하면 medium으로 올린다.

### STT는 되는데 재고 질문이 응급 분류로 간다

STT 문제가 아니라 라우팅 문제다. `"후시딘 있어?"`, `"밴드 어디 있어?"`는 `/api/classify`가 아니라 `/api/inventory/query`로 보내야 한다.

## 5. 비전 문제

### 정상 이미지를 출혈/화상으로 오탐한다

- confidence 임계값을 올린다.
- 자동 라우팅을 끄고 수동 선택으로 전환한다.
- 데모에서는 신뢰할 수 있는 샘플과 한계를 명확히 둔다.

### 이미지가 흐리거나 어둡다

- `poor_quality` 처리로 보수적으로 막는다.
- 조명을 고정한다.
- 카메라 위치와 초점을 고정한다.

## 8. 최종 모델 선택 요약

| 단계 | 기본 선택 | 대체 | 금지/비권장 |
| --- | --- | --- | --- |
| STT | whisper.cpp + Whisper small + CUDA | faster-whisper | large 모델 상시 사용 |
| LLM | Ollama + Qwen2.5 1.5B | llama.cpp CUDA + GGUF | 12B급 대형 모델 |
| 비전 | 현재 휴리스틱 검증 | MobileNet/YOLOv8n + TensorRT | VLM 진단 생성 |

**Xavier NX를 쓰는 방향은 맞다.** 단, "Ollama가 무조건 GPU를 쓴다"가 아니라 "Jetson GPU를 쓸 수 있는 경로를 실측하고, LLM 실행기는 Ollama와 llama.cpp 중 결과가 좋은 쪽을 채택한다"가 올바른 계획이다.
