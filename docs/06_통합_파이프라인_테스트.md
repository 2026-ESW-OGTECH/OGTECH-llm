# 통합 테스트: STT, LLM, 비전, 재고 검색

목표: 실제 데모 흐름에서 **음성 입력, 의도 분류, 재고 검색, 비전 플래그, 고정 카드 표시**가 안정적으로 연결되는지 확인한다.

## 중요한 수정 사항

`"후시딘 있어?"` 같은 문장은 응급 시나리오가 아니다. 현재 앱 구조 기준으로는 LLM 분류(`/api/classify`)가 아니라 **재고 검색(`/api/inventory/query`)**으로 보내야 한다.

따라서 통합 테스트는 두 경로를 분리한다.

```text
응급 발화
  → STT
  → /api/classify
  → scenario_id
  → safeaid_core.py 고정 카드

재고 질문
  → STT
  → /api/inventory/query
  → 물품 위치 안내
  → LED/서랍 제어
```

향후 마이크 버튼 하나로 둘 다 처리하려면 STT 결과를 먼저 **응급/재고 질문으로 라우팅하는 얇은 규칙**이 필요하다. 예: "있어", "어디", "꺼내줘", 물품명 포함이면 재고 검색 우선.

## 순차 실행 원칙

```text
[대기] 마이크 입력
   ↓
[① STT] Whisper CUDA로 텍스트 변환
   ↓
[라우팅] 재고 질문인지 응급 발화인지 판단
   ├─ 재고: inventory query
   └─ 응급: LLM/Ollama classify JSON
            ↓
          고정 카드 표시
   ↓
[선택] 사진 분석 버튼
   ↓
[③ 비전] 휴리스틱 또는 TensorRT 모델 → flags
   ↓
[표시] safeaid_core.py 고정 카드 / LED / 서랍
```

메모리 안전을 위해 STT, LLM, 비전을 한꺼번에 무겁게 올리지 않는다. Ollama를 쓸 경우 데모 직전 웜업은 하되, 실제 메모리 피크를 반드시 측정한다.

## 통합 측정 스크립트 개념

```python
# ~/safeaid_ai/pipeline_test.py
import time
from stt.stt_runner import transcribe
from llm.classify_test import classify

ITEM_HINTS = ["후시딘", "밴드", "소독약", "거즈", "연고"]
INVENTORY_WORDS = ["있어", "어디", "꺼내", "찾아"]

def route_text(text: str) -> str:
    if any(item in text for item in ITEM_HINTS) and any(word in text for word in INVENTORY_WORDS):
        return "inventory"
    return "emergency"

def run(wav_path: str):
    t0 = time.time()
    text = transcribe(wav_path)
    route = route_text(text)

    if route == "inventory":
        result = {"route": "inventory", "text": text}
    else:
        result = classify(text)

    print("TEXT:", text)
    print("ROUTE:", route)
    print("RESULT:", result)
    print("TOTAL_SEC:", round(time.time() - t0, 2))
```

이 스크립트는 개념용이다. 실제 앱 연동 시에는 현재 Flask API와 UI 흐름에 맞춰 호출한다.

## 지연 예산

| 구간 | 목표(웜) | 비고 |
| --- | --- | --- |
| STT | 1.5~3.0초 | whisper.cpp CUDA 기준 |
| LLM 분류 | 2.0초 이내 | Ollama 또는 llama.cpp |
| 재고 검색 | 1.0초 이내 | 로컬 데이터 기준 |
| 비전 | 1.0초 이내 | TensorRT 사용 시 |
| 음성 → 카드 표시 | 5.0초 이내 | 핵심 응급 경로 |

## 리허설 시나리오

| # | 입력 | 기대 경로 | 기대 결과 |
| --- | --- | --- | --- |
| 1 | "피가 나" | STT → classify | `bleeding` 카드 |
| 2 | "손을 베였어" | STT → classify | `cut` 카드 |
| 3 | "뜨거운 물에 데었어" | STT → classify | `burn` 카드 |
| 4 | "후시딘 있어?" | STT → inventory | 후시딘 위치 안내 |
| 5 | "밴드 어디 있어?" | STT → inventory | 밴드 위치 안내 |
| 6 | 상처 사진 | vision | `bleeding_possible` 또는 보수적 무응답 |
| 7 | 저전압/센서 이상 | safety | 자동 개방 차단 |

## 스트레스 테스트

- `jtop`을 띄우고 리허설 시나리오를 10회 반복한다.
- RAM/SWAP 피크가 누적 증가하는지 본다.
- 온도와 쓰로틀링을 본다.
- Ollama 사용 시 콜드/웜 차이를 기록한다.
- 네트워크를 끄고 오프라인 동작을 확인한다.

## 통과 기준

- [ ] 응급 발화가 올바른 `scenario_id`로 연결
- [ ] 재고 질문이 `/api/inventory/query` 경로로 연결
